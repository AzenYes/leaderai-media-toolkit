# 审片与修改：像挑剔的导演，而不是作品的粉丝

## 1. 什么时候看、看什么

| 节点 | 命令 | 看什么 |
|---|---|---|
| 代表帧 | `stills --at` | 静止时主次是否清楚、构图是否成立、和方向卡是否一致 |
| 核心动作小样 | `render --from --to` + `stills --range` | 弹簧、缓动、形变的手感；最难的镜头先做 |
| 每次大改后 | `verify` | 纯函数性、页面报错 |
| 全片草稿 | `stills --every 0.5`、`--scenes`、`--boundaries` | 节奏、死拍、重叠、出画、闪帧、接缝 |
| 手机可读性 | `stills --every 1 --phone` | 360px 宽时字能不能读，主体能不能看清 |
| 成片 | `qa_video.py --sheet` | 死区、跳变、闪帧、运动占比、响度 |

**联系表必须亲眼看（Read 图片）。** 自动检查只能缩小人眼要看的范围，替代不了人眼。运镜顺不顺，抽帧是看不出来的。条件允许时用浏览器打开 `film/index.html`，以正常速度通看一遍：空格播放，L 循环当前场景。

## 2. 打分（每轮都打，诚实打）

每项 1–10 分，并写出具体的时间点：

0. **故事清晰**：只读字幕能不能跟上？只看画面能不能猜到在讲什么？每章的问题和答案是否清楚？画面是否在解释“此刻那句话”？
1. **钩子**：前 5 秒内金句（大字）是否已经全部出完？有没有反常识的结论 + 数字 + 能截图的画面？第 0 帧是否已经在动？
1.5 **丰富度**：任意暂停一帧，能数出几层（背景氛围 / 环境运动 / 精细主体 / 信息标注 / HUD / 前景质感）？主体有几级细节？少于 4 层或主体只是几何形，就是“太简单”。
1.6 **设计秩序**：一个强调色相？三级字号？对齐？亮度层级是否清楚？
1.7 **变化频率**：每句都有大事件吗？句内每秒都有小事件吗？联系表（1 秒一格）里有没有连续 3 格几乎相同？
2. **概念**：一句话能不能复述？有没有“只属于这支片”的东西？最想截图的那一帧是否成立？
3. **层级**：每一刻只有一个焦点吗？主次比例是否清楚？
4. **运动质感**：缓动和弹簧有没有重量感？有没有 linear 的移动、滑而不停、抖动、残影？
5. **节奏**：有没有死拍？有没有太快读不完？节奏有没有起伏，还是一直一个速度？
6. **转场**：是形变或接续，还是淡入淡出加硬切？接缝处干净吗？
7. **画面完成度**：对齐、留白、字距、颜色是否都在 token 里？手机上能读吗？
8. **音画同步**：重音是否落在动作上？声音有没有糊成一团？

独立审片的做法：把方向卡、镜头表和联系表（`--every 0.5`、`--phone`、关键帧大图）交给一个新的子 agent，让它扮演“挑剔的资深动效导演”，按上面 8 项打分，每项给出带时间点的理由，最后列出影响最大的 5 条修改。不要告诉它你的自评分数。

**最差的 3 项要写出具体位置（时间 + 画面区域）并修掉，然后重新打分。** 每项都到 8 分以上才进入成片渲染。整片最多 3 轮；3 轮后仍有未达标的项，交付时如实说明（见 SKILL.md 的出口规则）。自评通常会虚高约 10%。条件允许时，派一个**没参与制作的子 agent**，只给它联系表和方向卡，让它按这份表独立打分，以它的结论为准。

## 3. 必须专门搜查的问题

- 换字时新旧文字叠在一起
- 被阅读的文字还在动
- 东西滑过去而不是缓入缓出（linear 移动）
- 角落标签、边框、居中加渐变的镜头
- 被放大的模糊文字
- 连续 2–3 拍什么都没发生，或者在重复同一个动作
- 特效盖住了字
- 元素出画、被裁、超出安全区
- 循环接缝的跳动
- 场景边界的闪帧（白帧、黑帧、层级错乱）
- 画面里的数字与来源不一致，示意数据没有标注
- 只画了一半的线、没闭合的形
- **安全极简病**：主体太小、大片空白、深色底、同一个版式从头用到尾、没有铺满画面的高潮帧。概念好但执行偏安全时，就是这个样子
- 结尾帧当海报看是否成立
- 同一版式是否撑了大半部片子（超过约 40% 时长）
- **亮度指纹**（qa_video）：亮部峰值、高亮像素占比、近黑帧占比是否落在目标区间；不达标说明主体太小太暗
- 同一个图表 / 刻度尺 / 卡片是否撑了 5 句以上而没有换景别
- **信息预算**：每帧除字幕外是否超过 1 处大字 + 2 处小字；冷开场 / 片名卡是否有小字
- 用 `review_pack.py` 的 transitions/ 和 motion/ 条带检查转场残影与死画面
- **摆着等字**：联系表里连续 3–4 格只有文字在变、主体纹丝不动，就是这个病。讲解片最容易犯
- **自定规则是否自洽**：本片定义的视觉编码（刻度越稀 = 时间越慢、面积 = 2^n、颜色 = 概念）在每个镜头里都成立吗？最想截图的那一帧有没有违反自己的规则
- 主体是否为了给文字让位而被缩小

## 4. 修改的方式

- **每轮只改 1–3 件事。** 一次贴七条意见，修改就变成了重写。
- **按“症状 → 原因 → 改法（带数字）”写修改记录**，记在 `work/film.md` 末尾：
  > 5.2s 右上：卡片落地像“滑停”（症状）→ 用了 outCubic，没有过冲（原因）→ 改成弹簧 170/22，过冲上限 12px（改法）
- 只重渲**受影响的那几秒**（`--from/--to`），确认之后再出全片。
- 不要用“更好看一点”这种模糊方向自己改，它只会带来随机变化。用镜头语言来改：“这个推镜放慢到 0.7 倍”“这里改成硬切”“推近到按钮上”。
- 某个问题连续 3 次修不好时停下来，记录原因，换一种实现方式，或者向用户说明取舍。

## 5. 接收用户反馈

用户的反馈常常是感受，比如“不高级”“有点乱”“太快了”。处理步骤：
1. 定位到具体时刻：先用 `stills --at <t>` 截出那一帧，亲眼看，再判断用户指的是什么。
2. 用 `运动语言.md` 第 10 节，把感受翻译成参数。
3. 已经认可的场景**不要动**。只修改被指出的部分，保持其他镜头的动作、时间和循环不变。
4. 回复时说清楚：改了什么、在哪一秒、哪些没能改以及原因。

## 6. 把教训沉淀下来

用户提出的每一条通用意见，比如“声音不要循环”“别照抄”“太快了”，都写进 `film.md` 的“本片规则”。下一轮或下一支片开工前先读一遍。只有确认是普遍有效的经验，才考虑回写到 skill 本身。
