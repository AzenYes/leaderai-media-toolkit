# 视觉系统：色彩、字体、构图、质感

## 1. 色彩

- **结构**：底色 + 墨色 + **1 个强调色**，必要时加一个次强调色，但要少用。每个场景最多 3 色（黑白不计）。语义色（颜色 = 概念）全片不超过 3–4 种，并且颜色一旦对应了某个概念就不再改变。
- **颜色要跟着剧情变**：用一句话写清全片的色彩弧线，比如“冷白 → 琥珀 → 红”。这一句话往往就能定下整支片的情绪。
- **在线性光空间混色**（`M.mixColor`），不要直接在 sRGB 里插值，否则中间色会发灰发脏。
- **雷区（AI slop 默认色）**：大面积紫蓝渐变底、深紫星空加霓虹、多色霓虹混用、满屏 bloom。问题不在“暗”和“光”，而在“没有系统”：发光只给主体、关键词、端点；星云/光斑压在背景层；全片一个强调色相。
- 想要层次，用**明暗两层平涂、纸纹、颗粒、暗角**，不要靠渐变底。
- 深色底和浅色底都可以很高级，取决于有没有**系统**：暗底 + 一个色相的克制发光 + 精细细节 + 层级（科幻 HUD、金融终端）是成立的；暗底 + 随意的紫蓝渐变 + 满屏粒子是廉价的。丰富度与层级的规则见 `丰富度与设计秩序.md`。

可直接起步、再按本片调整的色板（bg / ink / sub / accent / accent2）：

**这张表是起点，不是答案。** 不要每支片都从 paper 或 ink 起步：先从概念里推出颜色（这个主题在现实里是什么颜色？情绪弧线从哪里走到哪里？），再回来对照这张表。连续几支片都落在“米白 + 黑 + 橙红”或“近黑 + 橙红”上，说明你在用默认值。

**有品牌就用品牌色。** 从官网、logo 里取真实 hex，“永远不要用通用的 Tailwind 橙”。

## 2. 字体

- **字幕字体按内容在两种里选**：IBM Plex Sans SC（`Plex`，正文 500 / 强调 700）适合理性、科技、数据、机制；思源宋体（`HanSerif`，正文 600 / 强调 900）适合人文、历史、人物、情感、诗意。判断方法见 `叙事与字幕.md` 第 2 节。片名可以用宋体（`HanSerif`）或 Plex Bold。
- **一种展示字体 + 一种 UI/正文字体**，最多再加一种等宽字体做数字和 HUD。
- **字体必须子集化**：完整的中文 OTF 在 Chromium 里会报 CFF 解析错误，然后静默回退到系统字体。`new_film.mjs` 已经自动处理。改了屏上文字后要重跑 `python <skill>/scripts/fonts.py film/`；数字滚动这类运行时才生成的字，用 `--extra` 补进去。
- skill 字体（不随 skill 分发，首次使用自动下载，见 `assets/fonts/README.md`）：IBM Plex Sans SC 全部 8 个字重（Thin 100 → Bold 700，中文无衬线，西文与数字也很好）、思源宋体 SC 全部 7 个字重（ExtraLight 200 → Heavy 900，中文衬线）。字重多了也只在一处用一种：小字 Light/Regular，正文 Medium/SemiBold，大字 Bold/Heavy。系统里有其他已授权字体，也可以用 `@font-face` 引用。
- 引用网络字体时注意：渲染环境未必能联网。优先用本地文件，并且**等字体加载完再截第一帧**（引擎已经等待 `document.fonts.ready`，但 `@font-face` 字体只有被页面实际用到才会加载，所以要确保首帧就用上，或者调用 `document.fonts.load`）。
- 气质搭配参考：
  - 克制科技：Plex Sans，字重对比大（Light 小字 + Bold 大字）
  - 人文诗意：思源宋体 Heavy 大字 + 宋体 SemiBold 字幕 + Plex Light 小字
  - 节拍冲击：最粗的无衬线 + 斜体衬线做“人的那句” + 等宽做 HUD
- 中文排版：标点不出现在行首；大标题一行不超过 8–10 字；字距规则见 `运动语言.md` 第 8 节。

## 3. 构图

- **一屏一个焦点**；留白是主动的设计选择，不是没东西放。
- **不要**：居中标题加渐变底（默认外观的头号标志）、四角小标签和边框（除非 HUD 就是本片语法）、小物件漂在大片空白里。
- 有意识地选择构图：三分法、强对称、极端特写、大面积负空间、对角线、出画（主体被画框切掉一部分，会显得更大、更近）。
- **相邻两个镜头要换构图，不换画风。** 全片一套画风、一套色板：“干净统一但略像幻灯片的片子，胜过每镜换一种画风的拼贴”。
- 安全区：竖版 9:16 上下各留约 15%（平台 UI 会盖住），右侧留约 120px（点赞栏）；横版字幕带在下方 12%。
- 多画幅交付时，用**同一条时间线、分别重新排版**（场景布局写成函数，按宽高计算位置），不要直接裁切。

## 4. 质感

- 胶片颗粒：每 1/24 秒换一次种子（`M.rng(Math.floor(t*24))`），用 overlay 或 soft-light 混合，透明度 0.2–0.4。注意颗粒很吃码率：上传平台的版本降低颗粒强度，或者改成静态颗粒。
- 暗角：径向渐变 multiply，边缘压暗 10–20%。
- 纸纹、网点、套准偏移：属于媒介本身的质感。
- 景深：远处元素模糊加降低对比度。模糊要在小画布上做，或者预先烘焙，不要对全帧 canvas 每帧做 `ctx.filter = 'blur()'`，太慢。
- 色边、色差只放在画面边缘，或者只在冲击帧上出现。

## 5. 人物与插画

- 代码画的人物通常是短板。可以用剪影、手、背影、物件代替；需要具体人物时，用户提供的素材或生成图优先，代码负责合成和运动。
- 停用：代码画的 Q 版小人、白壳机器人、长了脸的物件（除非就是本片的角色设计）、stock 图标、emoji、灰色占位条。
- 一套图标统一描边粗细和圆角。
- 插画必须**展示它所对应的那件事**，不能放一张泛泛的装饰图。形状要完整闭合，不要只画一半的线。

## 6. 真实性

- 屏幕上的数字、名字、年份必须有出处（用户给的、可靠来源查到的）。**示意数据要在画面上标“示意”。**
- 产品界面只能裁切、放大、动画化真实截图或真实组件，**不要凭想象重画产品 UI**。没有截图时，用抽象的骨架线和形状，并且不冒充真实界面。
- 不要编造 slogan 冒充品牌的官方说法。
