# 叙事与字幕：用一句一句的文字把故事讲清楚

这类知识讲解动画**没有配音**。底部一行字幕就是“旁白”：它逐字显现、停留到读完、再换下一句。画面跟着这句话变化。所以字幕稿就是全片的剧本，写得好不好，直接决定观众能不能看下去。

## 1. 结构

```
开头金句（0–5s，1–2 句，标 "hook": true，大字显示）：一个反常识的结论或一个具体的人与悬念
    “你每天解锁手机 96 次”“可你只记得其中 3 次”（示意）
    “她每晚只睡四小时，却从不犯困”（示意）
片名卡（5–9s）：巨大的发光片名 + 英文小字 + 一句问题（这句问题就是全片要回答的）
    拖延的真相 / THE DELAY PARADOX / 为什么越想做的事，越拖着不做？（示意）
证据（研究 / 案例，3–6 句）：年份 + 谁 + 做了什么 + 发现了什么（带具体数字）
    “某年，研究者请两组人做同一件事”“一组有截止日，一组没有”（须换成可查证的真实研究）
机制（3–6 句）：为什么会这样？给它一个名字（“现时偏好”“拖延计时器”）
生活例子 × 2–3（每个 3–5 句）：观众自己遇到过的情境，配一个具体数字
    外卖晚 30 分钟 vs 晚 5 分钟；涨薪 500 元 vs 2000 元
升华（3–5 句）：这件事对“你”意味着什么，转折出一点温度
回到开头（2–3 句）：回到冷开场的画面，用新的理解重新看它；片名再出现一次
```

**节奏：第 0.3 秒出第一句金句，第 5 秒前金句全部出完。** 金句每句 ≤16 字，最好带一个数字；画面同时给一个大特写（一个人、一只眼、一个物），不要慢慢铺垫。

另一种开头（适合物理、宇宙、科技）：**结论先行**——“你头顶的时间，比脚下走得更快”“卫星上的钟，每天快 38 微秒”然后片名卡、再展开。两种开头的共同目标：**前 5 秒让观众想知道“为什么”**。标题式开场（“今天讲讲……”）和背景铺垫（“1988 年，霍金出版了……”）都不合格。

时长：默认 2–3 分钟，约 45–55 句字幕。用户给的时长优先；1 分钟约 18–22 句。讲不完就**选 2–3 个最惊人的点讲透**，其余不讲。

## 2. 写句子

- **一句一屏一行**：字幕 52px，单行最多约 30 个汉字宽，但为了阅读，中文 ≤ 20 字；长句拆成两句，靠断句本身把悬念留到下一句。超宽时 kit 会自动缩小字号并报警（不会换行或出屏），但缩小后就不统一了——看到报警就拆句。
- **句末不带标点**：每句字幕的最后不加句号、逗号、顿号、问号、感叹号、省略号、破折号；句中的逗号、冒号照常用。疑问和感叹靠措辞表达（“为什么会这样”“恰恰相反”）。`timeline.py` 会自动去掉句末标点并列出被改的句子，写稿时就别带上。引号、书名号这类成对符号的收尾保留（“他说：“我不困””）。
- **字幕字体按内容选**（不固定 Plex）。先问：这支片的语气更像“讲清一个机制”，还是“讲一个人、一段历史、一种感受”？
  | 用 IBM Plex Sans SC（`"font": "sans"`） | 用思源宋体（`"font": "serif"`） |
  |---|---|
  | 物理、宇宙、科技、数学概率、经济数据、生物医学机制、心理学实验、生活 UI 场景 | 历史人物、诺奖背后的人、书籍观点、哲学思辨、情感与关系、诗意的升华 |
  | 气质：精确、冷静、现代，数字和英文更清楚 | 气质：温度、叙事感、文学性，像旁白在讲故事 |
  | 正文 Medium 500，强调 Bold 700 | 正文 SemiBold 600，强调 Heavy 900（宋体横细，52px 下 600 才稳） |
  - **全片统一一种**写在 `lines.json` 顶层；只有语气明确切换时（如“机制”章节转到“人物”章节）才在章节内整段换，用单句 `"font"` 覆盖；同一场景内不混用。
  - 拿不准时：数字、术语多 → Plex；人和故事多 → 宋体。金句可以和正文同字体，也可以用宋体金句 + Plex 字幕制造“人的声音 vs 数据”的对照，但全片只选一种组合。
  - 片名卡、画面大字与字幕字体呼应：宋体字幕配宋体片名；Plex 字幕的片名可用宋体或 Plex Bold。
- **强调**：`[词]` 用 Bold 加主色（或 `K.caption.set(lines, {colors})` 里的角色色），每句最多 1–2 处。
- **一句一个意思，每句都能画出来**：有一个物、一个数字、一个动作或一个对比。只有抽象判断的句子，换成它的具体例子。
- **节奏**：短句制造停顿和力量（“没有”“恰恰相反”），长句交代信息；连续三句一样长会催眠。
- **口语、具体、有画面**：“比眨一次眼还要快几十倍”比“非常短暂”好十倍。
- 关键词用 `[ ]` 标出（字幕里用强调色显示），每句最多 1–2 个。数字是最好的关键词。
- **节奏标点**：短句（“没有”“恰恰相反”）也不带句末标点，停顿靠字幕停留和换句。
- 事实可核实：研究年份、作者、样本、数字都要查证；不编造名人原话；有争议的说“可能”“研究发现”。在 `work/film.md` 末尾列出处，必要时画面角落放出处小字（“MEDVEC · 1995”）。

## 3. 时间轴

```bash
python <skill>/scripts/timeline.py work/lines.json --film film/ [--beats work/beats.json]
```

- 每句停留 = `base + 字数 / cps`（默认 0.9 + 字数/6，12 字约 2.9 秒，约 2.5–3.5 秒一句）。信息密集、数字多的句子手动加 `hold`。
- 片名卡、章节卡、纯画面段写成 `"card": true`（不进字幕带），用 `hold` 指定时长。
- 每个新场景的首句加 `"scene": true`（片名卡和带 `at` 的句自动算），审片包会据此生成转场条带。
- 章节首句用 `at` 卡在音乐段落或大转场上；有音乐时加 `--beats` 让切换踩拍。
- 画面里所有时间都写成 `L.<id>.start + 偏移`。改稿后重跑 timeline.py，画面自动对齐。

## 4. 分镜：一句一个视觉节拍

把 lines.json 扩写成分镜表（写进 `work/film.md`）：

| 句 | 时间 | 这句让观众看懂什么 | 画面（主体在做什么） | 画面里的字（除字幕外） | 细节层（读数 / 标注 / 出处） | 和上一句的关系（延续 / 换场） |
|---|---|---|---|---|---|---|

规则：
- **字幕说什么，画面就演什么**：说“1 分是痛苦，10 分是狂喜”，画面上就出现 1–10 的刻度尺和打分指针；说“同样的 0.01 秒”，画面就是两条终点线和 0.01s 读数。
- **每句至少一个新的视觉事件**；句内约每秒一个小事件（标注生长、读数跳动、高亮扫过、粒子流动）。画面静止超过 2 秒就是死画面。
- **一个例子一个场景，场景内连续**：同一个例子的几句在同一个画面里推进（镜头推近、元素增加、状态改变）；换例子就换场景（遮罩、闪白、粒子散开重聚、镜头穿越）。
- 画面里的字只放这句的关键数字或关键词（“0.01 s”“14% → 96%”“快 20 倍”），不要重复整句字幕。
- 开头的画面在结尾再出现一次，但状态变了（同一块手机屏幕，这次多了一行用时统计）。
- 章节开头可以给一个小的章节标识，让观众知道讲到哪了。
