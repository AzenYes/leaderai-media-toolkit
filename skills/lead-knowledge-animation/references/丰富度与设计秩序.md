# 丰富度与设计秩序：复杂但不乱

“高级”不等于“极简”。观众觉得一个画面“高级、复杂、有信息量”，是因为画面里**同时存在多个层次的细节**，而且这些细节**有秩序**：一个主角最亮最大，其余按层级退后。只有主角、没有细节，画面就显得简单、像 PPT；细节全都一样亮，画面就显得乱、像廉价模板。

## 1. 六层结构（每一帧都检查）

| 层 | 内容 | 亮度/对比 | kit.js |
|---|---|---|---|
| ① 背景氛围 | 星云/雾/纸纹/渐变光/照片底图（降饱和、压暗） | 最暗（5–20%） | `K.amb` haze / wisp / warm、自定义纹理 |
| ② 环境运动 | 星点三层视差、微尘、网格、流线、远景粒子 | 暗（10–35%），永远在动 | `K.amb` stars / dust / grid / warp |
| ③ 主体 | 这句话要讲的那个物（精细绘制：刻度、高光、拖影、内部结构） | 最亮、最大 | `K.ctx` 或 DOM 里你画的东西 |
| ④ 信息层 | 关键词大字、数字读数、引线标注、单位、图例、小号英文副标 | 主字最亮，标注 40–75% | `K.text`、`K.callout`、`K.num`、`K.ruler`、`K.dial` |
| ⑤ 框架层 | 章节号 + 中英标题、时间码、进度条、右上角读数 | 很淡（30–50%），很小 | `K.hud` |
| ⑥ 前景与质感 | 虚焦光斑、镜头光斑、颗粒、暗角、偶尔的闪白/震屏 | 叠加，克制 | `K.amb` bokeh、`K.flare`、`K.flash`、`K.shake` |

**每个画面至少 4 层同时在场**（①②③④ 是底线），⑤⑥ 让它“像一部片子”而不是“一页动画”。

## 2. 主体要精细（复杂感的主要来源）

同一个“钟”，画成一个圆加一根线 = 简单；画成：表盘渐变 + 60 格刻度（每 5 格加粗）+ 外圈细环和四个刻线 + 内圈淡环 + 秒针扇形拖影 + 针尖发光 + 中心轴帽 = 高级。

给每个主体加 3–5 级细节：
- **结构**：内外多重轮廓、刻度、网格、经纬线、截面
- **光**：边缘高光（发光描边）、内部渐变、针尖/端点发光精灵、柔光晕
- **运动痕迹**：拖影、残影、轨迹虚线、速度线
- **数据**：贴在主体上的读数、坐标、单位、编号
- **材质**：点阵（地球大陆用点阵）、线框、粒子构成、纹理

真实数据会让画面瞬间可信：真实的地图轮廓（geojson）、真实的星图、真实的公式、真实的年份和数值。

## 3. 变化频率：让画面一直有事

- **句级**（2.5–5s）：一个大的视觉事件——新主体出现、主体变形、镜头推进、场景切换。
- **秒级**（~1s）：一个小事件——标注生长、读数跳动、关键词高亮、粒子流向改变、一个元素点亮。
- **持续级**：环境层永远在动（星点闪烁、微尘漂移、镜头呼吸）——它保证任何一帧暂停都不是死的。
- 章节转场是**最大的事件**：闪白 + 震屏 + 镜头光斑 + 音效重音，或跃迁拉丝，或主体坍缩成点再炸开。全片 3–5 次。
- 节奏要有起伏：信息密集段 → 一次“留白呼吸”（只有一个大数字或一句话，1.5–2.5s）→ 下一段。

## 4. 设计秩序（丰富而不乱的规则）

- **一个色相**做强调（科幻青、朱红、琥珀……），可加一个次强调色只用于“对立面/警示”。其余全部是墨色的不同透明度。
- **三级字号**：英雄字（72–160px）/ 正文与字幕（36–52px）/ 标注与 HUD（11–16px，字距 .2em，可用英文大写小字）。中间不要出现第四种随意的字号。
- **对齐**：大字、标注、HUD 都对齐同一套边距（如左右 56px、主字左边距 150px）。标注的引线水平或垂直，折一次。
- **亮度层级**：主体与关键词 100% → 次要信息 60–75% → 标注 40–55% → HUD 30–50% → 环境 10–35%。同时有两个东西 100% 亮，就要压掉一个。
- **发光要克制**：只给主体、关键词、端点加光；用发光精灵和双层描边，不用全屏 bloom。暗底 + 一个色相的发光是成立的视觉系统，问题从来不是“发光”，而是“什么都发光”。
- 网格、星点、粒子这些“丰富元素”放在背景层并且压暗。它们是氛围，不是内容。

## 5. 可以借鉴的“丰富”视觉系统（选一个起点，再按主题改）

| 系统 | 底 | 强调 | 丰富度来源 | 适合 |
|---|---|---|---|---|
| 科幻 HUD | 近黑蓝 #04070b | 青 #5be7ff + 琥珀 | 星云、视差星空、精细仪表、读数、蓝图网格、光斑 | 宇宙、物理、科技、未来 |
| 编辑拼贴 | 纸 #efe9dc | 朱红 #d7261e | 真实照片/扫描件、撕纸、网点、手写标注、红线、档案编号 | 历史、人物、调查、社会 |
| 数学黑板 | 深灰绿 #1e2a26 | 粉笔黄 + 珊瑚 | 公式推导、坐标系、函数曲线生长、几何构造线 | 数学、经济、原理 |
| 金融终端 | 黑 #0a0a0a | 荧光绿/红 | K 线、滚动行情、数据表、热力图、等宽数字 | 财经、数据、增长 |
| 生物显微 | 深海蓝绿 | 荧光粉/绿 | 细胞、分子、流体、焦外虚化、显微刻度 | 生命、医学、自然 |
| 胶片纪实 | 暖黑 | 琥珀 | 颗粒、漏光、档案画面、年份字卡、打字机标注 | 故事、人文、回忆 |

这些是**起点**：可以混合，但一支片只用一个主系统。

## 6. 主体的尺度与亮度（实测得出的硬指标）

对比被判“画面简单”的测试片和达标画面的逐帧量化数据，差距不在“元素多不多”，而在**主体够不够大、够不够亮**：

| 指标（去掉字幕带，每 2 秒取一帧） | 目标区间 | 测试片（被判“画面简单”） |
|---|---|---|
| 亮部峰值 p99 | 132–146 | 91–93 |
| 高亮像素占比（>110） | 1.5–2.4% | 0.7–0.8% |
| 画面平均亮度 | 17–20 | 12–14 |
| 近黑帧（85% 以上近黑）占比 | 17–39% | 38–58% |

`qa_video.py` 会自动给出这组“亮度指纹”，**上下限都检查**：太暗（主体小、空黑多）和太亮（均值 >24、高亮 >3.5%，雾和发光铺满）都不对——目标是“暗底上一个很亮的主角”。草稿阶段就跑，不达标先改亮度和尺度，再谈细节。

做法：
- **主体占画面 35–70%**：一个发光的大物体（眼睛、地球、大脑、舞台、跑步机、巨型数字）撑住画面；小卡片、细线条、小图标只能做配角。图表和 UI 卡片不能单独撑场，背后要有一个图像化的世界（地球、星空、神经网络、跑道、城市）。
- **每帧要有一个“亮核”**：`K.core(c, x, y, r)`（白色实心亮核 + 主色光晕），放在主体最重要的位置（光点、信号头、细胞核、数字落点、聚光灯焦点）。
- **开辉光层**：`Kit({ bloom: .9 })`（默认开启）只让亮部发光，细线和亮核会自然泛光。
- **背景不是死黑**：氛围光雾（haze .1–.2）+ 一层主题纹理（星空、神经网络、网格、巨字虚影）铺满，压到 5–15% 亮度。
- **景别变化**：同一个场景每句换一次景别（全景 → 中景 → 特写 → 拉回），用 `K.camKeys([[t, zoom, worldX, worldY, ease], ...])`；需要看微观就用 `K.lens(...)` 圆形放大镜。一个图表撑 5 句以上、一把刻度尺撑 10 句，是“变化少”的典型病因。

## 7. 本片画法库（core.js）

kit 提供的是通用原语。每个选题都会需要几个**专属主体**（工资条、跑步机、光缆截面、机房走廊、手机聊天界面、DNA 序列、实验装置……）。把它们写进 `film/core.js`，统一用同一套语言：发光描边（`K.glowLine`）、玻璃卡片（`K.card`）、亮核（`K.core`）、出处小字。主体画法要精细到 3–5 级细节，而不是一个矩形加一行字。

## 8. 有材质的主角（第二轮实测得出：比“变亮”更关键）

第二轮测试把亮度指纹拉到了达标线，但独立审片仍说“像一套很好的数据看板，不像一部光影片”。逐帧分析达标画面发现：好的主角是**有体积、有高光、有边缘光的插画式物体**——一颗有核的细胞、一只虹膜纤维清晰的眼睛、一棵发光的神经元、一块金属徽章——占画面 30–60%。细线、小亮点和 UI 卡片只是配角。

kit 提供了这类主角的起点（都是纯代码，确定性）：
- `K.orb(c, x, y, r, {color, nucleus, membrane, spec, rim, rx, ry})`：材质球 / 细胞 / 星体 / 果实 / 水滴 / 徽章胚子
- `K.branches({seed, depth, arms, len}).draw(c, x, y, p, {pulse, t, color, scale})`：神经元 / 树突 / 闪电 / 河网 / 血管 / 树
- `K.iris(c, x, y, r, {color, pupil, open})`：眼睛特写（开场极好用）
- `K.figure` 人形线描、`K.spotlight` 体积光、`K.sample`+`K.particles` 粒子成形、`G.globe` 点阵地球

选题里如果有具体的物（硬币、心脏、手机、杯子、钥匙、种子……），在 `film/core.js` 里按同样的语言画：**渐变填充出体积 + 一处高光 + 一圈亮边 + 外部光晕 + 3–5 级结构细节**。不要只画轮廓线。

## 9. 色彩：每个场景可以换主色

好的画面不是全片一个颜色：同一画面里三颗细胞是金、粉、蓝；章节之间冷蓝 → 绿 → 金 → 红轮换。规则是：
- **一个场景内**一个主色（加一个对立色），保持秩序；
- **场景之间**可以换主色，用来区分概念、章节和情绪；
- 全片共享同一个暗底、同一套字体和线描语言，所以换色不会乱。

## 10. 转场：不要默认交叉溶解

交叉溶解在暗底上会留下两层残影，三轮审片都扣分。优先用：
- **推近穿越**（`K.pushThrough`）：镜头推进眼睛 / 细胞 / 屏幕 / 门，满屏后切到下一场景；
- **圆形遮罩**（`K.irisWipe`）：新场景从一个点展开，或旧场景收成一个点；
- **光扫**（`K.lightSweep`）：一道光带扫过换场；
- **粒子散开重聚**（`K.particles` 反向再正向）；
- **硬切在音乐重拍上**，配一次闪白（≤ .25）或冲击音效。

## 11. 每段一个奇观（第二轮两支片的共同结论）

亮度、尺度、材质都达标之后，最后一道坎是**奇观**：每 15–25 秒要有一个让人想截图的画面（巨大的眼球、满屏神经元网络、粒子聚成的阶梯、放大到细胞的显微镜头）。两支测试片最强的画面都只是“一个大数字”或“一张图表”。

在分镜阶段，**每一章都要先写出它的奇观画面**，再写其他句子。奇观的来源：
- **尺度**：从一个人推进到细胞 / 从一座城拉远到整个地球 / 一个数字变成满屏 7,812 个点；
- **数量**：一个东西复制成成千上万个（粒子人群、细胞群、星系）；
- **材质特写**：主角推到占满画面，看到它的纹理、高光、内部结构；
- **变形**：一个物件变成另一个物件（舞台变徽章、+2,000 碎成粒子沉到习惯线、工资条卷成跑步机履带）；
- **光**：黑场里一束光打进来，或者满屏同时点亮。

奇观之后留一次暗场呼吸（0.8–1.5 秒，画面接近全黑只剩一个光点），然后进入下一段。明暗呼吸本身就是节奏，近黑帧比例不是越低越好（目标 17–39%）。

## 12. 长停留的拆法

联系表里连续 3–5 格（6–10 秒）几乎一样，就是长停留，即使每句字幕在变。拆法：
- 同一画面换 2 个机位：先全景，再推到正在讲的那个元素（`K.camKeys`），其余元素退暗；
- 让主角在这几句里持续做一件事（指针摆动、粒子流动、人在走）；
- 中间插一个 1.5 秒的特写或放大镜（`K.lens`）。

## 13. 每帧的信息预算（第三轮审片的主要扣分项）

“丰富”指的是**画面层次**（氛围、纹理、材质、光），不是**信息数量**。测试片的层次已经够了，审片扣分在“每帧小字偏多、信息层抢戏”。每帧的信息预算：

| 元素 | 每帧上限 |
|---|---|
| 主角 | 1 个（30–60% 画面），或 1 组同类物（群像、粒子）当作一个整体 |
| 画面大字（关键词/数字） | 1 处 |
| 小字（标注、读数、英文、出处） | 2 处（左上角章节角标另算） |
| 底部字幕 | 1 行 |

规则：
- **开头金句段和片名卡**：0 处小字，只有主角 + 金句大字 / 片名。冷开场构图要给金句留出画面中下部那条横带（约 H×0.62–0.76），主角放在上半部或两侧，别让大字压在主角身上（位置可用 `K.caption.set(lines, {hookY})` 调）。
- 并列比较（3 颗细胞、2 条曲线）时，并列物就是“主角”，每个最多配 1 个短标签。
- 一个信息点讲完就让它的标注退场，不要在画面里累积；读数、出处出现 2–3 秒后淡到 30% 或退场。
- 想放更多信息时，问自己：这句字幕已经说了吗？说了就不要在画面上再写一遍。
