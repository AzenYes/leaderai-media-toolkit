# 平台适配：重写入口、证据呈现和节奏

同一份素材可以复用，同一份成稿不能直接群发。改编时可缩短背景，但不能把局部结果改成普遍结论，也不能删掉限制留下更强承诺。平台规则会变：字数、标签、时长等不写成固定定律，发布前按当前平台确认。

## 一、中文平台

| 平台 | 写稿时优先处理 | 建议结构 | 结尾互动 | 边界 |
|---|---|---|---|---|
| 抖音 | 陌生观众迅速识别一个具体问题 | 现象 → 结果或判断 → 演示 → 一步行动 | 一个具体可跟做动作 / 可回答的小问题 | 用户协议要求题文相符；AI生成的非真实内容需按规定标识；不存在被证实的"黄金3秒"固定门槛 |
| 视频号 | 脱离作者背景也能看懂、能被转述 | 共同情境 → 判断 → 真实示范 → 可复述结论 | "转给正在××的同事/朋友"式的自然转交理由 | 写稿时自问"谁会把它转给谁、转发时想表达什么"；不据此认定受众年龄 |
| 快手 | 过程和结果本身清楚、真实 | 场景 → 行动 → 结果 → 经验 | 朴素真实的提问 | 社区规范反对骗点击、骗赞 |
| 小红书（视频） | 观众能判断是否适合自己的场景 | 对象与条件 → 经验或示范 → 步骤 → 限制 | 引导收藏备用 / 具体提问 | 只有本人真实用过才说"我的"；商业合作需按规定标注 |
| B站 | 标题承诺能否在完整过程里兑现 | 问题 → 成品 → 章节式过程 → 验证与排错 → 清单 | 指向合集/下一期相邻问题 | 重真实与完整；中长视频要给章节和失败分支，不是把短视频拉长 |
| 知乎（视频/回答） | 直接回答问题并给出处 | 答案 → 理由 → 证据 → 反例 → 边界 | 邀请补充反例 | 引用研究要说明它研究的是什么场景 |
| 微博 | 事实、来源和个人判断分开 | 事件与时间 → 出处 → 判断 → 讨论 | 具体讨论问题 | 标注信息来源；不靠机械互动 |

## 二、海外平台

| 平台 | 优先处理 | 建议结构 | 边界 |
|---|---|---|---|
| YouTube 长视频 | 包装承诺、观看体验与满意度 | 完整展开，章节化 | 回看峰值可能是精彩也可能是没听懂 |
| YouTube Shorts | 一项独立完整的价值 | 问题 → 示范 → 一步行动 | 没有最低发布频率要求 |
| TikTok | 快速识别任务并持续交付 | 钩子 → 主体 → 收尾（候选结构） | "前3–6秒"来自广告指南，不当自然推荐法则 |
| Instagram Reels | 原创且视觉有新增价值 | 一个视觉主题 → 具体解释 → 自然互动 | 重视原创，搬运内容受限 |
| LinkedIn | 专业受众能学到并行动 | 工作问题 → 依据 → 启示 → 讨论 | 不照搬煽动式开头 |

## 三、同题多平台改写示范（主题：把"功能介绍"改成"能跟做的教程"）

- **抖音/快手/Shorts（一个问题、一次示范）**："'这个功能可以有效提升编辑效率。'听完你知道点哪吗？换成'先选中这两段，再点合并'，观众马上能跟做。写教程先查三件事：对象说清了吗、动作说清了吗、做完该看到什么说清了吗。拿你的旧稿找一句功能介绍，改成一个具体动作，再念一遍。"
- **B站（保留过程和失败分支）**：看原稿 → 明确观众起点 → 抽象功能改成动作 → 安排录屏与口播分工 → 试读并指出仍会误解的位置 → 给检查表。
- **视频号（可转交）**："团队里有人要录第一条教程口播，可以先把这三类长句拆开。"后面给可复现的例句。
- **小红书视频（可保存步骤）**：开头点问题，中段句子对照，结尾给检查表与不适用情况。

## 四、画面、口播、字幕分工

- 口播解释"为什么这么做"，画面/录屏展示"怎么做"，字幕突出要记住的动作、数字和限制。
- 字幕不能删掉限制条件（例如"先备份，再覆盖"）。
- 去掉跨平台残留：别的平台的按钮名、口令、"点击左下角"等。
