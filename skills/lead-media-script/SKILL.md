# Lead-自媒体口播文案

目标：用户只给一个简单想法，也要交付一份**吸引人、能兑现、念得顺**的口播逐字稿，并以两个本地文件（纯口播文案 + 执行方案）作为最终交付。

吸引力来自三件事，不来自夸张：
1. **具体的受众任务**：观众一听就知道"这说的是我"；
2. **可兑现的承诺**：标题、封面、开头、正文说的是同一件事，正文真的给到；
3. **低理解成本**：听一遍就懂，念一遍不卡。

方法依据来自本地调研（20个平台、80张技巧卡）。细节按需读取 `references/`，不要一次全读：

| 文件 | 何时读 |
|---|---|
| `references/结构库.md` | 第3步选结构时 |
| `references/开头与标题.md` | 第4步写开头、第6步写标题封面时 |
| `references/平台适配.md` | 用户指定平台，或要求多平台版本时 |
| `references/审稿清单.md` | 第7步自检时；用户要求"改稿/审稿"时直接走这个文件 |

## 四条铁律（优先级高于"更吸引人"）

1. **不编造**：不虚构亲身经历、测试结果、数据、粉丝评论、朋友故事、平台规则或算法权重。需要这些才更有说服力时，写成 `【待补：你真实的××，例如……】` 占位，并在稿后列出。
2. **不夸大**：不用"最强""全网第一""100%""必火""节省80%"等无法证明的说法；不为制造焦虑夸大后果；不藏起会改变理解的关键信息来骗完播。
3. **事实先于文风**：先确认说的是对的，再润色口语；涉及版本、价格、功能、政策等易变信息，标注"需发布前核实"。
4. **局部修改不全稿重写**：用户只要求改开头/某段时，只动那一部分。

## 工作流程

### 第1步：解析想法，补齐默认值（默认不提问）

从用户输入里提取下列要素；缺失的按默认值补上，并在交付开头用一行"本稿假设"说明，用户可随时纠正。

| 要素 | 默认值 |
|---|---|
| 平台 | 竖屏短视频（抖音/视频号/快手通用） |
| 时长 | 60–90 秒（约 250–380 字，以本人试读为准） |
| 内容类型 | 按想法判断：教程 / 观点 / 测评 / 经验故事 / 避坑 / 资讯解读 / 种草带货 |
| 目标受众 | 从选题推断最具体的一类人，不写"所有人" |
| 口吻 | 第一人称、像对一个朋友讲，口语、克制、不喊麦 |
| 本条主要目标 | 教程→跟做；观点→讨论；测评→帮选择；种草→了解适配后行动 |

**只在一种情况下先问**：缺少的信息会让稿子方向完全不同（例如"推广我的产品"但不知道是什么产品），此时用一个问题问清，最多附 2–3 个选项。其他情况直接写。

### 第2步：写出"观看承诺"与事实底稿（内部完成，简要展示）

- **任务句**：`谁，在什么场景，遇到什么阻碍，看完能做到什么`。例："第一次录教程的人，写完稿一开口就卡，看完能把功能介绍改成能跟做的句子。"
- **一句话承诺**：这条视频到底回答什么问题。
- **事实底稿**：分三栏——用户已给的事实 / 通用常识可写的内容 / 需要用户本人补的（经历、数据、截图）。
- **数据开头素材**：从事实底稿里挑出可以当开头的数字，标明类型：可验算的数学（如"亏50%要涨100%回本"）/ 用户提供的数据 / 有原始出处的统计。没有可靠数字就不硬造，第4步改用其他机制。
- **增量检查**：至少有一条比"随手搜到的内容"多的东西：一个具体例子、一个反例、一个适用边界、一个失败后怎么办。没有就自己构造**明确标为示例**的教学例子。

### 第3步：选结构

读 `references/结构库.md`，按内容类型选结构，并给每段标注"作用"（提出问题/给答案/证据/解释/处理异议/行动）。每段必须有工作，删掉不影响主线的段落就删。

### 第4步：写 3 个不同机制的开头候选

读 `references/开头与标题.md`。三个候选必须**机制不同**（如：结果先看 / 具体场景 / 反常识但准确 / 具体问题 / 代价明确），每个注明"正文第几段兑现它"。选一个推荐写入正文，并说明理由。

**数据优先规则**：只要有事实数据支撑，★推荐开头**优先用"数据反常识结论"**——第一句就抛出一个具体数字，直接推翻观众的直觉（例："亏百分之五十，要涨多少才能回本？不是百分之五十，是百分之一百。"）。要求：
- 数字必须可验证：可验算的数学 > 用户提供的数据 > 有原始出处的统计；来源不明的流传数字（如"七亏二平一赚"）不用。
- 结论必须真的反直觉，且直观：一个数字、一组对比就能听懂，不堆多个数据。
- 优先选不依赖假设的数字；依赖假设的（如费率、时间跨度），在"需核实"里写明假设和换算后的范围。
- 数字后面紧跟一句"所以呢"，把它接到本条主题；正文要回扣这个数字，但不重复同一句算式。
- 画面同步上大字（如"-50% → +100%"），停顿放在推翻直觉的那一拍前。
- 没有可靠数据时，不为了用数据开头而造数字，改用其他机制，并在"待补"里提示用户可以提供什么数据。

开头要求：前一两句就让目标观众识别"这说的是我的问题"；不寒暄、不自我介绍、不说"今天给大家分享干货"。

### 第5步：写逐字稿（口语化）

- 常用词 + 具体动词："选中这两段，再点合并"，不说"进行段落选定操作"。
- 一句只推进一个意思；长句拆短，但不机械统一长度。
- 代词要有明确指向；术语第一次出现给一句大白话解释。
- 每 15–25 秒给一个新信息点（新例子、转折、反例、结果），而不是重复同一观点。
- 删掉"毋庸置疑""非常重要的是""那么接下来"等空泛套话。
- 结尾回扣开头的承诺，只给**一个**最主要的行动（跟做一步 / 回答一个具体问题 / 收藏备用），不堆一串三连。
- 真实感来自选择理由和细节（"这里我停一下，因为下一步最容易点错"），不来自编造的失误。

### 第6步：包装

- 标题 3 个（不同角度：明确收益 / 具体问题 / 条件对比），每个都能在正文找到兑现段落。
- 封面短句 2 个（与标题互补，不重复同一句）。
- 用户指定平台时，按 `references/平台适配.md` 调整结构、节奏和结尾互动。

### 第7步：自检后再交付

按 `references/审稿清单.md` 快速过一遍（承诺一致、无编造、难念句、重复段、单一行动）。发现问题先改再交，不把问题留给用户。

### 第8步：保存两个交付文件到本地项目文件夹（每次必做）

文件才是正式交付结果，对话里的内容只是预览。每次写稿、改稿、出新版本都要保存成文件，不用等用户提醒。

- **位置**：当前工作目录（项目根）下的 `口播文案输出/YYYYMMDD 主题/`。已有 `口播文案输出/` 就沿用，没有就新建；日期用项目日期，未明确时用当天北京时间；主题取 2–6 字短名（如"散户亏钱"）。同一选题的后续版本放进同一文件夹。用户当次指定了路径时，以用户指定的为准。
- **两个文件**（`标题` 用推荐标题或选题短名，去掉文件名中的非法字符）：
  1. `纯口播文案_标题.txt`：**只放要念的话**。段落之间空一行；不含 markdown、标题、段落作用标注、"/"停顿符、〔画面〕提示；有【待补】占位就原样留在句子里，方便录之前替换。
  2. `执行方案_标题.md`：首行写 `# 执行方案：标题`，下面按「交付格式」完整写入（本稿假设、一句话承诺、事实底稿、开头候选、带"/"和〔画面〕的口播逐字稿、标题封面、录制提示、待补/需核实）。
- **不覆盖**：同名文件已存在时，按场景加后缀区分，如 `_1分钟版`、`_v2`、`_v3`；局部改稿也另存为新版本，旧版保留。
- **交付回复**：对话里照常展示交付内容，并在末尾列出这两个文件的路径（可点击的链接）。保存失败时如实说明原因，并把完整内容保留在对话里。

## 交付格式

按以下顺序输出，标题用 markdown，正文可直接复制去录：

```
**本稿假设**：平台｜时长约X秒（约N字）｜类型｜受众｜目标（如有误告诉我）

## 一句话承诺
……

## 开头候选（3选1，已选★）
1. ★【数据反常识】……（兑现：第2段；有可靠数据时优先）
2. 【具体场景】……（兑现：第3段）
3. 【反常识】……（兑现：第2段）
推荐理由：……

## 口播逐字稿
（纯净逐字稿，可直接念；段落间空行；需要停顿处用"/"，需要画面配合处用〔画面：……〕）

## 标题 & 封面
- 标题：①… ②… ③…
- 封面字：①… ②…

## 录制提示
- 画面/录屏/字幕要突出的关键动作或数字
- 最容易念卡的 1–2 句及替代说法

## 待你补充 / 需核实
- 【待补】处列表（没有就写"无"）
- 需发布前核实的事实
```

用户只要"一版短的"或"直接给稿"时，可省略开头候选与录制提示，只保留假设行、逐字稿、标题、待补项。

以上格式就是 `执行方案_标题.md` 的内容；`纯口播文案_标题.txt` 只取其中的「口播逐字稿」，并去掉停顿符和画面提示（见第8步）。

## 多版本与改稿

- **多平台版本**：同一素材按平台**重写入口、证据呈现和节奏**，不是改几个字群发；每版只保留一项完整价值。
- **改稿/审稿**：用户给出已有稿件时，先按审稿清单列"问题位置—原因—最小修改"，再给修改稿；不改变作者立场、不补造经历。修改稿同样按第8步另存为新版本的两个文件。
- **复盘**：用户带来发布数据时，按 `references/审稿清单.md` 的复盘部分，把曝光、点击、开头流失、中段流失、互动分开诊断，每次只建议一个主要改动。
